## 0. 当前实施范围与框架优先原则

用户已授权开发，并将范围从单 H 扩展为 **A/G/H 三种开机动画全部可预览，最终采用哪种由用户比较后决定**。暂保留 H 为兼容入口的预览默认，不视为最终产品选择；模拟器增加 `--boot-animation A|G|H`，不增加持久化产品设置或自动循环。

先建立能够随需求增长的私有 UI 框架，再接入三种动画：

- 公共 API/页面切换只负责入口、生命周期和查询；页面持有自己的状态，不向跨页面全局结构不断追加字段。
- 页面、可复用组件、共享视觉原语/主题、生成资源、离线工具和测试分目录；私有头文件跟随所属模块，不能把页面内部对象暴露给宿主。
- 依赖方向为宿主 → 公共 facade → 页面 → 组件/视觉原语/资源。传感器、存储、RTOS 和显示端口留在宿主，新增业务数据用明确类型及有界回调进入 GUI owner；不从控件直接调用平台服务。
- 同一页面内部出现独立职责时继续拆分，例如语言页的面板/保存状态与滚筒手势/吸附；开机页的生命周期、公共场景和各变体轨道分别归属，不堆进一个 switch 大文件。
- 新页面必须同时定义 create/destroy、异步工作取消、数据输入/操作输出和测试；新增复用组件先由实际复用需求驱动，不提前建设路由器、事件总线、依赖注入或 Motion Engine。
- 手写 C 文件以约 250 行为维护目标，超过 350 行必须检查职责是否需要拆分；生成数组除外，生成器按资源家族输出并核算完整资源量。不能为了满足行数机械拆函数。
- 具体目录、分工和新增需求接入规则维护于私有 `ui/docs/ARCHITECTURE.md`；后续产品源码、设计源和验证图像仍留在私有 `ui/`。

三种动画共用官方 0.82 比例轮廓、A8 填充图形/六字形、原生 Timeline 与启动门控。H 沿用第 4 节；新增的 A/G 差异为：

| 方案 | 原生实现路线 | 入场 / 最短保持 / 退出 |
| --- | --- | --- |
| A | 官方轮廓离线细分后由 `lv_line` 逐段描边；550–900 ms 填充交叉渐显；原生背景渐变遮罩形成约 30 px 羽化边缘，不退化为硬裁剪 | 描边 0–800，字标显现/居中 950–2050，保持至 2650，退出 320 ms |
| G | 图标 0–700 ms 渐显并上移；六字形作为整体从图标后方滑出；裁剪边固定在原始 x=176，而非随字标移动 | 字标滑出/居中 900–2100，保持至 2800，退出 320 ms |
| H | 狭缝裁剪、六槽确定性解码，按原生 Timeline 编排 | 入场至 643，保持至 839，退出 99 ms |

A 的轮廓点表单独计入预算，不引入描边序列帧或运行时矢量后端；允许整数坐标约 1 px 量化差异，必须视觉核对。三方案共用字形资源而不是保留三套完整 Logo；A 的描边品牌表现仅作为用户指定候选，最终采用仍需用户确认。三者都通过无请求保持、请求退出、提前换页/销毁和最小软件配置验证。

后文原有 H 专项要求继续适用；旧文中“单 H 本阶段”的范围以本节为准。审核约束没有因扩展范围被豁免。

**当前交付状态：** 框架、A/G/H、按钮反馈及普通/最小软件构建已完成；自动回归和关键帧检查通过。60 Hz 桌面环境下已请求并检查 VSYNC，已消除静态阶段无效重绘；连续内容变化的 57–60 FPS 分段验收尚未完成，不能用包含静态保持或 H 解码停顿的整体间隔替代。详细证据、资源统计和未验证边界见私有 [ui/docs/VALIDATION.md](../ui/docs/VALIDATION.md)。最终动画选择与实板验收仍由后续阶段决定。

## 1. 决策与范围

本阶段先建立可扩展 UI 框架，在 macOS 模拟器建立 **60 Hz 目标刷新能力**，实现 **A/G/H 三种候选开机动画**供用户选择，并使同一 `ui/` 源码具备交给固件集成的条件。

采用：

> **LVGL 原生控件与样式状态 + 原生动画/时间线 + 按需选用的绘制与素材能力；以软件绘制建立固件兼容基线。**

充分发挥 LVGL 的含义是让框架承担它已经擅长的布局、交互、状态过渡、动画编排和绘制，而不是自行实现这些机制。A8 是 H 品牌字形的合适资源格式，不是整个 UI 的技术上限；固件约束用于预算和验收，不预先禁止矢量、复杂渐变或 Lottie。

核心原则是：**模拟器负责预览与调试，共享 UI 负责效果；固件继续拥有显示驱动、内存分配、任务调度和启动决策。**

### 本阶段包含

1. 模拟器从当前约 30 Hz 调度调整为 60 Hz 目标刷新，验证实际节奏。
2. 实现 A/G/H：描边与羽化、固定裁剪滑出、狭缝与六槽解码；共用品牌字形、居中和退出生命周期。
3. 实现启动就绪交接、重复进入、取消、页面销毁及资源清理。
4. 建立原生动效使用规范：H 使用 `lv_anim_timeline` 编排，现有确认按钮采用样式状态 transition；统一曲线/时长、取消和清理，不重新实现 LVGL 调度器。
5. 增补可控时间的动画测试、关键帧对照及软件绘制兼容性验证。
6. 提供固件接入契约、配置依赖和资源预算。

### 本阶段不包含

- 修改固件、Beken SDK、面板时序、旋转路径、触摸映射、DMA/ISR 或 Flash 分区。
- 承诺 BK7258 实板达到 60 FPS，或承诺固定上电首帧时间。
- 实现尚未集成的首页、称重页面、OTA 资源包系统。
- 引入 Lottie、ThorVG、运行时 SVG、视频或全屏序列帧作为 H 的运行依赖。
- 建立通用动画脚本系统、特效注册中心或自动画质调节引擎。

### 1.1 LVGL 原生优先的能力分层

| 能力 | 本阶段或后续使用原则 | 固件边界 |
| --- | --- | --- |
| 原生控件、事件与状态 | 新界面优先使用 button、label、bar、arc、chart 等对应控件，不把整页截图当 UI；保留现有已满足交互契约的自定义滚筒 | 按需启用使用到的控件，不为展示能力全开 |
| 共享 style / theme、状态 transition | 本阶段用共享品牌参数及 `lv_style_transition_dsc_t` 完成按钮按下/释放反馈；后续选中、禁用沿用相同机制 | transition 描述和属性数组必须在使用期间有效；不因视觉过渡延迟业务状态生效 |
| `lv_anim` / `lv_anim_timeline` | 普通属性变化用动画，H 和多阶段组合用原生 Timeline；使用原生暂停、重播、进度定位，不写通用播放调度器 | 生命周期归页面；取消 Timeline 后再删对象 |
| Flex / Grid、滚动与吸附 | 后续列表、弹窗及多语言布局优先原生能力；H 固定品牌几何仍使用明确坐标 | 不为套布局系统改坏现有设计；布局位置与动画属性不互相争夺 |
| 原生图形、渐变与图片变换 | 线、圆弧、进度、边框优先控件/绘制 API；局部渐变、缩放和旋转按效果需要使用，而非统一转成图片帧 | 记录脏区、变换缓冲及 Alpha 开销；不能把桌面表现直接当作实板性能 |
| Screen / Layer / 页面过渡 | 新页面真正采用独立 screen 时优先 `lv_screen_load_anim`；本阶段保持既有页面入口，不为开机强改整个页面管理 | 内置 screen 转场期间输入受限、双页面有内存成本；有可中断交互要求时采用局部容器动画，不盲用全屏淡化 |
| Observer / 数据绑定 | 后续同一 UI 状态确实驱动多个控件时，优先 `lv_subject` / `lv_observer`，不另造 UI 通知框架 | 只在 GUI owner 中更新 subject，不把 observer 当跨线程队列；不为 H 或每个单一字段强行引入 |
| Canvas / Vector / Lottie | 保留为正式可选路线；按具体效果比较原生绘制、矢量、Lottie 和局部预渲染的视觉/开发/运行成本，不一律退回位图 | 选用前确认固定固件构建的后端、依赖、资源峰值与实板效果；不等同默认所有效果都具备这些能力 |
| Profiler / 性能监控 | 开发测量优先使用 LVGL 已有事件、监控或 profiler，再补最少的宿主汇总 | 按需启用；性能测试与高开销诊断分开，固件发布配置独立决定 |

本阶段明确落地 **Timeline + 样式 transition + 原生对象/图片/裁剪**。其他能力是后续效果的优先选型规则，不表示现在重做所有页面或一次实现完整组件库。

### 1.2 真正与 LVGL 9.6 相关的收益

以本地 `lvgl/docs/src/changelog/CHANGELOG.mdx` 和固定源码为依据：

- **软件混合与变换路径优化**：9.6 的直接收益之一；A8/Alpha 与局部变换并不是“绕开新版本”，恰好使用其软件绘制基础。官方其他芯片的提速数字不能套用到 BK7258。
- **公开/私有 API 分离**：共享 UI 只包含公开头文件，不依赖 `src/` 内部结构或 `lvgl_private.h`，降低两端补丁差异带来的移植风险。
- **专用对象状态 API 与参数检查**：新增代码优先使用两端已具备的 `lv_obj_set_disabled()`、`lv_obj_set_checked()` 等公开接口；开发构建保留适当的参数检查/日志。参数检查不能替代错误处理和生命周期管理。
- **默认样式缓存及局部失效优化**：沿用框架能力，避免每帧重建样式、控件或无差别整屏失效。
- **字体/文本能力改进**：后续动态读数优先原生 label 与合法可部署的字体；按需评估 text leading trim、二进制字体动态字形加载。FreeType 可变字重不作为固件默认依赖。
- **配置体系整理**：以固定 9.6 配置和迁移说明核对双方能力，不复制桌面配置到固件，也不为使用新特性升级 SDK。

Timeline、transition、Flex/Grid、Observer、Lottie 等是 **9.6 可使用的 LVGL 能力**，不把它们全部宣传为 9.6 新增。

现有 OPPO 固定文案位图有字体许可背景，不能因改用原生控件而擅自改造或分发字体；品牌字形也仍使用官方轮廓。原生文本路线需在字体许可与固件资源均满足后采用。

## 3. 模拟器 60 Hz 方案

### 3.1 区分三个不同指标

1. **LVGL 更新周期：** 动画推进、对象失效及绘制调度的时基。
2. **窗口呈现频率：** SDL 向系统呈现新画面的频率。
3. **物理显示器刷新率：** macOS / 显示器控制的扫描频率。

本方案要求模拟器支持 **60 Hz 级动效预览，并在 60 Hz 显示环境验收接近 60 FPS 的连续动效**。它不通过程序擅自修改用户显示器设置，也不声称提供硬实时 60.000 Hz。

### 3.2 实现路径

**第一步：调整模拟器自己的 `lv_conf.h`。**

- 将 `LV_DEF_REFR_PERIOD` 从 33 改为 **16 ms**。
- 保持 RGB565、LVGL 软件绘制和现有 SDL backend。
- 不把此文件复制进 `ui/` 或要求固件沿用。
- 本地 LVGL 的动画 timer 同样使用 `LV_DEF_REFR_PERIOD`，不能只提升 display timer 而遗漏动画更新。

**第二步：启用并核查 SDL 垂直同步。**

- 在模拟器 HAL 创建窗口后，通过现有公开窗口接口取得 SDL renderer。
- 在 SDL 版本支持时调用 `SDL_RenderSetVSync(renderer, 1)`，检查返回结果；记录实际显示模式及 VSYNC 请求结果。
- 本地 SDL 提供该接口；其他开发环境需版本检查及明确的降级日志，不为此升级系统工具或修改 LVGL 子模块。
- 60 Hz 显示环境作为正式节奏验收环境。120/144 Hz、可变刷新率或 VSYNC 不可用时，记录实际呈现结果，不把它冒充锁定 60 Hz；首版不额外引入跨刷新率限帧器。

**第三步：保留现有事件循环。**

- 继续由主线程调用 `lv_timer_handler()`，遵循其返回的等待时间。
- 不追加固定 `SDL_Delay(16)`，避免与 LVGL 等待及 VSYNC 叠加而降到 30 FPS。
- 使用真实经过时间推进动画，不通过“每帧加一”决定动画状态。
- 空闲页面允许不绘制，不以强制整屏刷新制造 60 FPS 数字。

**准确口径：** 16 ms 本身对应约 62.5 次/秒的调度上限，并非精确 60 Hz；接近 60 FPS 的呈现由显示环境、VSYNC 与实际负载共同验证。VSYNC 请求成功也不单独作为实际帧率通过证据。

### 3.3 最小性能记录

性能记录仅放模拟器，不进入共享 UI 的运行依赖：

- 内容持续变化区间的刷新间隔、P95、最大长帧；
- 可区分时分别记录 CPU 软件绘制、flush/SDL present 及 VSYNC 等待耗时，无法区分则说明统计边界；
- 通过现有公开事件/诊断能力记录合并后重绘面积或脏区规模替代指标；可获得时记录绘制任务数及 A8/Alpha 混合面积估算，并注明估算方法，不为统计依赖私有结构或修改 LVGL Fork；
- 开机动画关键阶段及实际切页时间；
- 创建前、动画峰值、销毁后的 LVGL 内存；
- 测试时长、样本数、窗口遮挡状态、显示模式、VSYNC 结果和配置；
- macOS 窗口逻辑尺寸、drawable 像素尺寸与 Retina/HiDPI 缩放；关键帧比较固定使用 960×376 LVGL 逻辑画布，不使用经系统缩放的桌面截图尺寸替代。

24 个场景对象仅作为资源预警，不作为帧率预测依据；重绘面积、Alpha 混合量与内存访问成本需结合帧时间判断。

H 的字符按源周期 66 ms 切换。定稿把播放压到 1000 ms 后，屏幕上约每 20.5 ms 一步，这是设计节拍，不是掉帧。静态停留段也不纳入连续动画 FPS 统计。

## 4. H 动画的共享实现

### 4.1 视觉与素材

基准文件：`Mistro-boot-anim-AGH/variant-H.html`、`storyboard-H.png`、`mistro-tokens.css`。

- 背景：Ink `#0A0D12`。
- 图形：Frost `#D6E2EC`；RGB565 输出允许量化后的合理色差。
- 最终组合约 463×85 px，以示例 SVG 的 0.82 比例及坐标为准。
- 保留图标与字标的原始轮廓、间距和位置；不重新排字、不调用系统字体代替品牌字形。
- 动态过程不缩放 Logo、不模糊、不弹跳。

离线生成以下 A8 素材：

1. 一个品牌图标（A/G/H 共用）；
2. `M / i / s / t / r / o` 六个独立字形；
3. 一个用于解码的短条素材；
4. 素材原点、槽位、偏移等小型常量表。

素材必须保存原始坐标到裁剪图像原点的映射，特别是小写字母、`i` 的点和基线位置，不能把裁剪后的图片各自居中后替代官方布局。

所有生产源码、原始品牌路径和生成资源存放在私有 `ui/`。普通 CMake 构建只编译生成后的资源，不依赖用户设计目录、Python、浏览器或联网下载。

**A8 着色契约（R03）：** A8 仅存 Alpha。沿用现有 `image_source()` 的公开属性设置方式，明确设定 `image_recolor = Frost`、`image_recolor_opa = LV_OPA_COVER`，以 `image_opa` 控制局部透明度。当前固定源码的 A8 无变换软件路径直接使用 `draw_dsc->recolor` 作为颜色，再混合 Alpha 和图片透明度；不能按普通 RGB 图片的 recolor 强度推断 A8 颜色，也不能省略颜色设置而依赖默认白色。

生成物检查 `lv_image_dsc_t` 的 magic、`cf = LV_COLOR_FORMAT_A8`、宽高、stride、data_size、像素偏移与目标配置的对齐要求。素材裁剪原点与图像绘制偏移分别记录，不把紧密排列或其他宿主的对齐条件默认为固件条件。

### 4.2 场景结构

- 一个内容定位容器，负责整体重新居中；不对它做整树透明度动画。
- 图标置于一个矩形裁剪容器中，通过裁剪区域高度变化形成狭缝展开。
- 六个固定尺寸槽位，每个槽位一个 `lv_image`；切换字形时保持槽位位置不变，按源坐标调整图像偏移。
- 通过正常父对象裁剪限制槽位内容；保持 overflow visible 关闭，不依赖示例备注中不存在的 `OVERFLOW_HIDDEN` 枚举。
- 渐显、解码透明度及退出淡化作用于局部图片的 `image_opa`，避免整屏或整容器 Alpha 中间层。
- 应用层不在逐帧回调中创建/删除对象或分配新图片；字形未变化时不重复设置图片源。

预计场景约 15–20 个对象，工程预算上限先定为 24 个；超过时说明原因，而不是堆叠无用容器。

### 4.3 时间线

已确认设计稿把方案 H 单次播放定为 1000 ms。槽位的出现、解码和定字仍用原来的 3220 ms 源时间，播放时钟用 `playback * 3220 / 1000` 映回源时间。下表左边是播放时间。A/G 不使用这套压缩。

| 播放时间 | 效果 |
| --- | --- |
| 0–193 ms | 图标中心狭缝展开（源时间 0–620） |
| 217–326 ms | 组合宽度扩展，整体重新居中（源时间 700–1050） |
| 约 248 ms 起，每槽错峰约 8 ms | 六个字符槽位依次出现（源时间 800 起，每槽 25 ms） |
| 解码阶段，约每 20.5 ms | 切换字形及约 42–60% 透明度（源周期 66 ms） |
| 约 419 / 438 ms | `s / t` 开始确定字形（源时间 1350 / 1410） |
| 约 497 / 516 ms | `r / i` 开始确定字形（源时间 1600 / 1660） |
| 约 575 / 593 ms | `M / o` 开始确定字形（源时间 1850 / 1910） |
| 各字形确定后约 50 ms | 透明度从 75% 过渡到 100%（源时间 160 ms） |
| 643 ms | 最终 Logo 全部完成（源时间 2070） |
| 至少停留至 839 ms | 保持最终画面，等待交接条件（源时间 2700） |
| 允许退出后 99 ms | H 退出渐隐（源时间 320 ms）；约 938 ms 淡完。预览末尾约 62 ms 空白是成片停止，产品不因此自动结束 |

进入/居中及定字渐显采用 `cubic-bezier(.16, 1, .3, 1)`，退出采用 `cubic-bezier(.7, 0, .84, 0)`。

**曲线实现契约（R02）：** CSS 曲线必须先按时间 X 反求参数，再取得 Y，不能把四参数 CSS 曲线直接替换为单维 `lv_bezier3()`。已核查本地固定 LVGL 的公开 `lv_cubic_bezier(x, x1, y1, x2, y2)`：实现包含牛顿迭代及二分回退，确实按 X 反求参数；`lv_anim_path_custom_bezier3()` 经内部路径调用它。因此原计划先验证 `lv_anim_set_bezier3_param()` + `lv_anim_path_custom_bezier3()`，而不是直接认定语义不兼容；是否采用仍由精度测试决定。

- 以 `LV_BEZIER_VAL_MAX` 换算控制点并记录舍入规则；当前 1024 标度四舍五入后，两条曲线分别为 `(164, 1024, 307, 1024)` 和 `(717, 0, 860, 0)`。
- 实施时以参考 HTML 的 `bez()` 反求结果为基准，比较两条曲线的归一化采样、阶段端点、指定关键帧及映射到实际几何/透明度后的误差；源码语义相符不等于定点精度已经验收。
- 仅当实测精度/成本不达标时，才离线生成整数 LUT，记录控制点、采样数、生成方法及误差，运行时整数插值。128 个 `uint16_t` 点/曲线可作候选，两条共 512 B，必须计入预算；不能把候选采样数直接当作精度保证。
- 固件固定源码的接口、精度和构建可用性仍在接入阶段核对；不以新增 LUT 替代两端验证。

**实施精度结论：** 固定版本的原生 10-bit 求解器在 1025 个输入点上，进入/退出曲线最大误差分别为 7/1024、22/1024，未通过原 4/1024 阈值。因此按上述回退规则，使用 `tools/generate_boot_curves.py` 生成两条 128 点 uint16 LUT（合计 512 B），由 LVGL 原生动画路径回调做整数插值；没有修改 LVGL 或引入额外调度器。离线密集采样最大归一化误差 0.000219356；运行路径的 117→463 几何误差实测不超过约 0.575 px。永久回归阈值反而收紧到 1/1024，不放宽原失败测试。

退出请求已经到达时，H 从开场到淡出结束约 938 ms（839 + 99）。这不是上电到可操作时间，也不是把预览成片的 1000 ms 当成硬件承诺。计时在场景构造完成、Timeline 启动时开始，不把素材/对象创建时间计入展示时长。淡出结束前一直停在 HOLD，没有 `po_ui_boot_request_exit()` 不会自己变成结束。

### 4.4 驱动方式

- **使用 `lv_anim_timeline` 作为 H 入场的统一编排器**：图标裁剪展开、组合宽度/居中、六个字符槽位分别组织成 `lv_anim` 轨道。几何曲线由 LVGL 管理；每个槽位用一个确定性视觉状态函数统一处理隐藏、解码、定字和渐显，不为解码与定字分别建立透明度写入轨道。
- 组合宽度和居中使用同一轨道值计算，避免两条位置动画造成不同步；槽位回调一次求出图片源、源坐标偏移及 `image_opa`，不依赖历史帧数、回调顺序或完成回调留下的状态。
- Timeline 统一各轨道时间，不创建每字母独立 timer，也不手写覆盖整个 H 的全局帧调度器。
- 字符轨道从入场 t=0 开始，传递未经缓动的播放时间。槽位函数先按 `playback * 3220 / 1000` 得到源时间，再按 `appear` 和 `resolve` 计算每槽局部阶段，出现前明确写回隐藏状态。解码序列及透明度表离线从参考 HTML 导出，不引入随机库；索引保留全局相位 `floor(源时间 / 66)`，不能错改成从每槽 appear 时刻重新计步。低帧率直接采样当前状态，不补播过期帧。
- 各几何属性只有一个入场轨道；启用适当的 `early_apply` 使反向 seek 到轨道开始之前也恢复初值。不能简单关闭所有 `early_apply` 而留下上次定位的状态。
- 入场结束后保持最终状态；839 ms 最短展示和宿主就绪条件由启动状态管理，必要时只使用一次性等待。允许退出后，入场 Timeline 已完成或明确暂停，才将透明度写入权交给 H 的 99 ms 退出动画。A/G 的退出仍是 320 ms。
- 测试及内部预览用 `set_progress()` 定位、`pause()` 暂停、`start()` 从当前进度继续、`restart()` 从头重播；用 `get_playtime()` 和 `LV_ANIM_TIMELINE_PROGRESS_MAX` 换算并限幅，不硬编码旧版进度范围。视觉 seek 不伪造已经等待的启动时间或宿主就绪状态。
- 本阶段不再包装一层通用 timeline 调度系统。

这保证同一段代码在 30 Hz 与 60 Hz 下具有相同的总时长和最终状态，只是运动采样密度不同。

### 4.5 属性写入所有权（R01）

| 对象/属性 | 唯一更新来源 | 交接与复位约束 |
| --- | --- | --- |
| 图标裁剪矩形的高度及垂直位置 | 图标展开轨道 | 从一个进度计算，中心不漂移；不由布局器覆盖 |
| Logo 容器宽度及整体位置 | 居中轨道 | 同一进度求值；回到 700 ms 前恢复初始几何 |
| 每槽图片源、相对偏移和 `image_opa` | 该槽位唯一视觉状态函数 | 隐藏、解码、定字、渐显统一求值；每次可还原完整状态 |
| 图标 `image_opa` | 创建时设为不透明；退出时由退出动画接管 | 入场无第二条透明度动画 |
| 退出期间所有图片 `image_opa` | 独立退出动画 | 入场停止写入后接管；不对容器做整树 opacity |

乱序定位在暂停且未进入退出阶段的入场 Timeline 上测试；1933 → 300 → 1500 → 2700 ms 的目标画面应与独立从头运行到相同采样点一致。超过入场末尾的定位只限幅到最终 Logo，不触发生产退出请求。H 的入场是 643 ms，上述较晚采样点会停在最终 Logo。退出中重播需先取消退出动画和旧等待、重置场景状态，不能让入场与退出同时写图片透明度。

## 5. 启动交接及生命周期

### 5.1 公共接口增量

保留原有公共接口签名，三方案实施增加：

```c
/* 当前为 boot 时登记退出请求；重复请求无副作用，其他页面忽略。 */
void po_ui_boot_request_exit(void);

/* 当前 boot 已完成退出渐隐时为 true；其他页面或销毁后为 false。 */
bool po_ui_boot_is_finished(void);

/* 三方案预览入口；默认入口保留 H，无效枚举回退 H。 */
void po_ui_show_boot_variant(po_boot_variant_t variant);

/* NONE / ENTERING / HOLD / EXITING / FINISHED；用于稳定帧捕获与状态查询。 */
po_boot_state_t po_ui_boot_get_state(void);
```

现有 `po_ui_show_boot()` 改为创建并播放 H；每次调用均先清理上一页面及动画，再开始新的一次播放。该行为变化必须写入 UI 版本交付说明。

无需新增异步回调：宿主在已有 GUI 调度循环中检查完成状态，避免完成回调中销毁正在执行的动画上下文。

### 5.2 状态与规则

```text
播放 H → 最终 Logo 停留
            │ 已收到退出请求，且原始最短展示时间已到
            ▼
         渐隐（H 99 ms，A/G 320 ms）→ 完成 → 宿主切到已经准备好的下一页
```

- 宿主只在下一页面所需条件准备好后请求退出，不在 UI 内等待网络、存储或传感器。
- 请求早到：记录请求，仍完成正常展示。
- 请求晚到：保持最终 Logo，请求到达后再开始渐隐。
- 请求缺失：UI 保持最终 Logo，不自行淡出黑屏或重复闪烁；固件长期未就绪时，由宿主决定故障提示、重试或恢复策略，不能将模拟器预览保持行为照搬为产品无限等待策略。
- 宿主发现启动错误或需要立即换页时，可直接调用现有页面切换/销毁接口中断动画。
- 完成标记出现后，宿主必须在下一次 GUI 调度机会切页，不能把已渐隐的空画面当成等待态。
- 页面销毁必须先暂停并删除 Timeline、退出动画和一次性等待，之后再释放/清理对象和状态；不能只依赖 LVGL 删除对象时清理绑定到对象的动画。

所有 UI API、动画启动、查询和销毁都在平台已有 LVGL 调度/锁上下文中执行。来自其他任务的启动就绪、故障或休眠消息先交给 GUI owner。

### 5.3 模拟器各入口

| 入口 | 计划行为 |
| --- | --- |
| 普通启动，无有效语言偏好 | 播放 H；语言页条件准备好后请求退出；结束后进入语言选择 |
| 普通启动，有有效偏好 | 播放 H 后进入语言选择，已保存语言只作为初始选中项；确认后进入 mode 1 ready |

## 7. 固件可运行性契约

### 7.1 共享 UI 必须满足

- 标准 C99；仅使用两端固定 LVGL 9.6 均提供的公开 API。
- 不包含 SDL、POSIX、桌面文件路径、系统字体、RTOS、Beken 驱动或硬件寄存器调用。
- 不读取/修改全局 display 颜色格式、刷新周期、缓冲数量或旋转设置。
- 本阶段核心必需能力为软件绘制、A8 图片、现有页面控件、矩形裁剪、原生动画/Timeline 和样式 transition；这不是后续 UI 的永久能力上限。
- 核心配置关闭 ThorVG、Lottie、SVG、GIF、FFmpeg、桌面字体后仍可构建并执行 H 及现有页面。后续增强效果单独声明依赖；它们不能反向成为 H 的隐藏依赖。
- 使用固件已有 LVGL 内存分配路径，不自行分配 framebuffer，不默认独占 PSRAM。
- UI API 由 GUI owner 调用；固件内部绘制 worker 的并发由其 LVGL port 管理。
- 相同代码允许宿主采用 30 Hz 或 60 Hz，不把 Mac 的调度速度作为动画正确性条件。

### 7.2 固件端未来需提供

1. 现有 960×376 逻辑画布、合法 tick、GUI 调度和 LVGL 锁上下文。
2. 兼容的 LVGL 9.6 公开接口及 A8 软件绘制配置。
3. 启动状态通知，以及在下一页准备好后的退出请求和切页操作。
4. 页面关闭/休眠时，在显示停止排空之前清理动画及 UI owner 工作。
5. 将共享库接到固件构建：固件可提供兼容的 `lvgl` CMake target，或由现有组件构建注册同一批 UI 源码；不把桌面父工程一起搬过去。

**原生 376×960 扫描与 960×376 逻辑方向继续由固件现有适配负责。** 不在共享 UI 中新增二次旋转。

固件可以根据可靠的启动原因选择完整播放或直接进入已有业务页面。首次开机、普通开机、短间隔重启和休眠/震动唤醒分别制定策略，测量上电首帧与真正可操作时间；是否缩短/跳过动画不由 UI 猜测，更不在此阶段修改电源逻辑。缩短版应从完整参考时间线派生，不在 P2 随意改变关键帧。

### 7.3 核心配置与可选增强能力

不维护两套独立产品 UI，也不建立自动画质引擎。共享代码按实际采用的 LVGL 能力组织：

- **核心配置**：本次 H、样式反馈和现有页面完整运行，不依赖桌面专有能力；作为必须通过的固件兼容基线。
- **可选增强能力**：确有矢量/Lottie/复杂绘制需求时，记录所需 LVGL 配置、后端、额外工具链、素材和峰值内存。模拟器可先验证视觉，但未获固件验证的效果明确标为候选，不能标成已经可移植交付。
- 每个被产品采用的增强效果，在交给固件前要么确认目标配置能够完整运行，要么提供经过视觉确认的核心实现；纯装饰效果可明确选择不播放。关闭增强配置后不能缺少必要状态反馈或无法链接。
- Lottie 若被采用，优先使用内嵌数据入口，避免桌面文件路径；ThorVG 引入的 C++ 构建/链接要求及 ARGB8888 渲染缓冲必须单独核算。例如 463×85 的单个输出缓冲约 154 KiB，尚未计入解析器、场景和缓存。
- 基础配置验证不等于验证全部增强效果；每新增一个实际使用的能力，扩展对应测试，而不是默认全量开关通过即可。

### 7.4 资源预算

以下为首版设计预算，需实现后实测替换：

| 资源 | 预算/策略 |
| --- | --- |
| H 图标、六字形、短条 A8 净像素 | 目标不超过 48 KiB；预计约 33–40 KiB，包含必要留白后复算 |
| 解码序列及定位表 | 小型常量表，目标不超过 1 KiB |
| 曲线数据 | 实测启用两条 128×uint16 LUT，共 512 B；精度证据见 4.3，不藏在像素预算内 |
| H 额外 LVGL 动态内存 | 相对空白页目标不超过 64 KiB，需覆盖创建峰值、播放及退出；不含公共 framebuffer 与静态素材 |
| 应用层逐帧分配 | 不创建新图像缓冲或对象；LVGL 内部开销仍需测量 |
| 全屏动画中间层 | 不新增 |
| 常驻运行负担 | 播放完成并停留后没有为解码持续运行的定时器 |

若实测超过预算，先查对象数量、透明层、图片解码及重复素材，不以调大桌面堆作为修复。

静态 `const` 数组在固件中的实际驻留位置由链接和内存映射决定，不能仅凭 C 声明认定“完全不占 RAM”。提交时报告资源净数据、链接后的只读数据增长和运行时动态峰值，三者分别列出。

**完整资源收支（R04）：** 当前生成源码回读得到 83 个 A8 数组、495,135 B 净像素。旧开机 `po_asset_symbol` 为 160×160，`po_asset_wordmark` 为 243×66，共 41,638 B；当前 UI 源码的使用点仅在 `po_ui_show_boot()`。实施时仍需重查全部引用，并同步生成器、生成声明及资源定义，不能只手删生成数组或误删其他页面素材。

| 情形 | 全部 UI 净像素数据 | 相对 512 KiB 参考容量的净余量 |
| --- | ---: | ---: |
| 当前 83 个数组 | 495,135 B | 29,153 B |
| 替换旧开机资源，H 为 33–40 KiB | 487,289–494,457 B | 36,999–29,831 B |
| 替换旧开机资源，H 达到 48 KiB 上限 | 502,649 B | 21,639 B |

以上仅是以旧素材能够完整移除为前提的像素收支预测，不含描述符、对齐、表、代码或链接器保留项，也不表示素材已生成/删除或固件链接已通过。不去重直接新增会超出这个参考值；不能据此直接判定实际固件分区已超额。

三方案生成物已核对：保留 80 张文字与 globe 共 453,497 B，移除旧开机两图 41,638 B，新增共用开机 8 张 A8 共 28,172 B；当前全部 UI 净像素 **481,669 B**，比原来减少 13,466 B。语言像素、宽高与 stride 已逐项比对保持一致。A 另有 138 个点及累计长度表，解码表 348 B，描述符/对齐/链接占用另计；不能把像素总量当作完整固件占用。

P2 必须交付“新增、删除、保留、最终总量”的逐项清单，分别报告净像素、C 数组实际大小、描述符/对齐/常量表、宿主链接后的只读数据增量及各方案动态峰值。固件预留的 512 KiB `ui_resources` 尚不是可用的外部资源加载系统；第一版仍采用 C 数组，真实固件的 Flash/RODATA 增量、AP/OTA 容量和驻留区域必须留到固定固件 linker map 核实。宿主链接数值不能冒充固件数值。

## 8. 验证与验收

### 8.1 功能与生命周期

- 对照 H 的 300、800、1000、1200、1433、1700、1933、2500 ms 采样。入场在 643 ms 结束，更晚的采样停在最终 Logo。
- 对照最终轮廓、间距、基线和居中；像素取整允许约 1 px 的位置差异，RGB565 色差单独判读。曲线须同时通过数值采样与阶段节奏检查，不能只凭最终位置一致判断合格。
- 增加早请求、晚请求、无请求、重复请求退出的测试。
- 验证播放中切语言页、销毁、重复进入，以及渐隐中被中断。
- 无 SDL 测试用虚拟 tick 推进，不通过真实 sleep 等待动画；分别测试 pause→start 续播、restart 从头播放、中间进度续播，以及乱序 seek `1933 → 300 → 1500 → 2700 ms`。图片源、透明度、偏移及容器位置不依赖历史顺序，并与实际 tick 采样一致；记录进度换算的毫秒取整，额外覆盖 appear/resolve/66 ms 切换边界。
- 用 16/17 ms、33 ms 和一次较大时间跳变验证采样：总时长和最终字形不随帧数改变，不积压过期解码帧。
- 验证确认按钮 transition 在快速按下/释放、键盘焦点和 disabled 切换下不会延迟操作、重复触发或遗留错误颜色；样式描述生命周期有效。
- 反复创建/销毁后动画数量及可观测内存回到基线，无旧场景回调影响新页面。
- 原有语言拖动、吸附、误触取消、保存失败重试和偏好行为继续通过。

A8/RGB565 软件绘制需单独覆盖：不透明区为 Frost 而非默认白色；半透明边缘无黑/白边及异常色晕；解码透明度变化不闪屏；裁剪第一/最后一行无错位或残像；图片格式、stride、偏移和对齐有效。对照基准使用逻辑画布输出，不能用桌面 GPU 后端结果代替软件路径验证。

### 8.2 模拟器 60 Hz

使用 Release 构建，在记录过的 60 Hz 显示环境及非遮挡窗口上验证：

- 记录 VSYNC 状态和实际刷新间隔，不能只截图 FPS 计数器。
- 在连续运动/淡化区间，目标呈现接近 60 FPS（建议正常负载下约 57–60 FPS），P95 帧间隔目标不超过 25 ms。
- 无可稳定复现的持续性长帧、30 FPS 锁定或双重 sleep；大于 50 ms 的离群帧需记录上下文。
- H 的源周期 66 ms 字符切换（播放约 20.5 ms）、阶段停顿和最终保持不作为掉帧统计。
- 性能采集不与高开销截图、资源生成或 Debug 重检查混跑。
- 若 VSYNC 或宿主环境无法满足上述条件，标明“已设置 60 Hz 目标、实际呈现未达标”，不填写为通过。

### 8.3 固件兼容性代理验证

在不操作硬件的前提下完成：

1. 共享 UI 正常构建及现有 headless 测试通过。
2. 提供隔离的最小软件配置构建：RGB565、A8 开启，SDL/ThorVG/Lottie/SVG/视频/系统字体关闭；沿用 CMake 和真实 LVGL，不另造 mock 渲染器。当前父工程无条件查找 SDL 并链接 `lvgl::thorvg`，兼容性构建需显式隔离这些宿主入口/依赖，只构建 LVGL、`lib-ui` 和无 SDL 测试；不能只关闭宏就声称通过。测试专用配置不是交给固件使用的 `lv_conf.h`。
3. 验证共享库无 SDL/宿主符号依赖；在 C99、公开 LVGL API 和最小配置下运行 A8/RGB565、H Timeline、Style Transition 及页面生命周期测试，不仅验证能够链接。
4. 记录两端 LVGL 固定版本/补丁差异和使用的配置能力，不盲目同步 SDK 或 Fork。
5. 输出资源体积及动态内存报告，明确是否达到第 7 节预算。

这能证明共享代码不依赖桌面特性，**不能替代固件交叉编译、链接预算和实板性能验收**。本阶段不默认触发固件构建、烧录或设备测试。

## 10. 方案结论

**本阶段提供 A/G/H 三种候选，最终选择留给用户。** 三者优先使用小尺寸 A8、原生线条/渐变/裁剪和 Timeline；按钮反馈采用样式 transition。本次无需运行时矢量或视频，并不意味着后续效果禁止使用这些能力。

**整体路线是 LVGL 原生优先，不是位图优先。** 普通控件、状态过渡、组合动画、布局、数据绑定和绘制，先选框架已有能力；素材格式与高级后端按视觉需求和实测成本决定。

**模拟器提升到 60 Hz 目标刷新，但共享 UI 不拥有或强制这个刷新配置。** 同一 UI 在固件不同刷新频率下仍按真实时间正确运行。

**固件可运行性的交付标准是：依赖可移植、资源可核算、生命周期明确、最小软件配置可运行；实板帧率与业务并发由后续固件验收决定。**

本文件是实施依据，不是验收结果。开发已开始；完成与未完成的构建、视觉、性能及固件验证须在交付记录中逐项说明。
